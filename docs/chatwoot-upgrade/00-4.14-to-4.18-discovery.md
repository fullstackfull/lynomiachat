## 4. Inventory by topic

### 4.1 Backend extension mechanism (how Lynomia hooks in)

Lynomia uses Chatwoot's own extension mechanism. It does not edit core models.

- `lib/chatwoot_app.rb:28-38` (upstream code, unmodified) already knows about a `custom/` folder: `self.custom?` and `extensions` → `%w[enterprise custom]`.
- `config/application.rb:51-57` (Lynomia) eager-loads `custom/app/**`, prepends `custom/app/views` and appends `custom/db/migrate` to the migration paths.
- `config/initializers/01_inject_enterprise_edition_module.rb:82-87` (Lynomia) makes `const_get_maybe_false` return `false` when the extension namespace is missing. This fixes booting with `custom/` but without `enterprise/`.
- `config/initializers/billing.rb:5-12` (Lynomia) includes three modules on every reload:
  - `Billing::AccessGuard` into `Api::V1::Accounts::BaseController`;
  - `Billing::InboxLimit` into `Inbox`;
  - `Billing::AgentLimit` into `AccountUser`.
- `custom/app/models/custom/account.rb` is picked up by upstream's `Account.prepend_mod_with('Account')` (`app/models/account.rb:221`). It adds `has_one :billing_subscription`, `after_create_commit :start_billing_trial` and `before_destroy :cancel_stripe_subscription`.
- `config/routes.rb:719` (Lynomia) calls `draw :billing`, which loads `config/routes/billing.rb`.

## 6. Conclusion of discovery

- The fork is a thin, well-isolated layer on top of v4.14.1. 46 of its 127 files live in `custom/`, and it uses upstream's own `custom` extension point.
- A real git merge of `v4.18.0` is possible. The expected textual conflict surface is small (9 text files, plus assets).
- Nothing found so far requires deleting a Lynomia customization. This is re-checked after the merge in the regression phase.
